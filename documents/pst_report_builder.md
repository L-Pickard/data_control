## Refresh refactor checkpoint — 21 October 2026

Before refactoring, the existing PST work was committed in data_control as `f7d8f1a` and dashboard_app as `6cc57bf`. The new refresh implementation is a separate commit and can be reverted without undoing the checkpoint. Pre-existing modifications to fnc_is_customer_exclusion.sql and fnc_is_customer_intercompany.sql were left outside both commits.

The local update_pst_table implementation now:

- Serializes refreshes using the transaction application lock `dbo.update_pst_table` (immediate refusal if busy).
- Holds the editor's `portal.pst-report-edit` resource shared for the transaction, snapshots report options and PST exclusions, and retains HOLDLOCK definition reads until commit. Portal saves use the same resource exclusively.
- Builds the selected entity list per report, aggregates sales once into all fourteen shipped measures, and separately aggregates inventory, purchase orders and sales orders before joining them.
- Uses report-specific NOT EXISTS exclusions instead of repeating scalar functions per item/measure. Global rules are not automatically added.
- Caches distinct nonblank Ltd shipped/open order IDs once when a report needs them. B.V shipped orders match sales.order_no across all Ltd sales history (original Finance behavior); open orders match sales_orders.document_no for document_type=1. Whole-order suppression is independent of the selected company set and of customer/date filters on Ltd matches. Blank/NULL IDs never suppress another order. The two flags act independently.
- Restricts open quantities to document_type=1 and sales line_type=2. Purchase loaders already populate item_id only for item lines; NULL/blank item IDs are excluded.
- Builds each candidate item list from its selected, filtered aggregates, joins dbo.items for the authoritative brand, and requires a matching dbo.brands row. Unknown items/brands and items that occur only in excluded companies/rules are omitted. Valid zero-net rows are retained.
- Atomically replaces all results and updates each built report's UTC last_updated only after every report succeeds. Computed averages remain table-owned. Caller-owned transactions are left open for the caller; errors are rethrown.

`tools/check-pst-refresh.ps1` rewrites the actual procedure against local temporary fixture tables/procedure and unique test lock resources; it does not run the real refresh or write warehouse data. It verifies seven report scopes, master-item/brand filtering, per-target exclusions, global-rule separation, order types, independent B.V flags including BV-only scope and blank IDs, all date boundaries and fractional returns/averages, repeat-run equality, success timestamps, rollback of a forced insert failure and caller-owned transaction behavior. The original check-pst-shipped-columns.ps1 now delegates to this fuller check. Production-schema compilation/sp_refreshsqlmodule was also tested in a rolled-back transaction without executing the refresh.

The refactored procedure is not deployed or run against real facts. Finance and source servers are untouched. No elapsed-time performance claim is made; actual plan/timing validation remains a deployment check. Git revert restores source only, not deployed database definitions or data.
