# PST Report Builder persistence

Consolidation deployed and verified on 21 October 2026 (schema version 5). The existing report retains ID 1, both enabled checkbox flags, revision 2, edit metadata and refresh timestamp; its 76 PST exclusions and all 125 global rules are preserved. Both old tables are absent and the FK is trusted/enabled. Preview rebuilt and restarted; page and library API verified.

Company selection deployed on 21 October 2026 (schema version 6): `include_ltd`, `include_bv`, `include_llc` are NOT NULL bits defaulting to 1. Existing reports retain all three companies. The save procedure and editor read/write each choice independently; no exclusions are deleted when a company is unticked. The unfinished result generator must apply these flags when it is implemented.

Current definitions live in `portal.pst_reports`: ID, name, company inclusion flags, independent Sales/Sales Orders B.V/Ltd exclusion flags, concurrency revision, last edit metadata and the preserved report refresh timestamp. No change history is stored. PST-specific rules remain in `dbo.exclusions`; its FK references `portal.pst_reports`. `dbo.fnc_is_pst_exclusion` reads those same rows unchanged. Global rules are not modified.

Canonical definitions are `sql/tables/portal/pst_reports.sql`, `sql/procedures/portal/save_pst_report.sql` and `sql/tables/dbo/exclusions.sql`. The obsolete `sql/tables/dbo/pst_exclusions.sql` catalogue definition has been removed. The user's work-in-progress `sql/procedures/dbo/update_pst_table.sql` now reads the portal catalogue; its remaining work is preserved and not deployed automatically.

`sql/migrations/20261021_consolidate_pst_reports.sql` consolidates the originally deployed schema version 4 into version 5, preserving IDs, names, both checkbox values, revisions, edit metadata, refresh time and exclusion rows. It checks copied values, redirects the FK and drops both `dbo.pst_reports` and `portal.pst_report_settings` inside a single transaction together with installing the updated save procedure. The earlier version 4 migration is historical and must not be rerun after consolidation.

`tools/check-pst-report-builder.ps1` exercises the latest company-selection migration and create/edit/validation/concurrency behavior inside a rolled-back transaction. Live runtime grants already cover the portal schema and save procedure, so no new permissions are needed. `sql/database/grants_pst_report_builder.sql` is updated for fresh deployments and must be run by a Windows db_owner if required.

Keep `dbo.potential_sell_through` in dbo: it is calculated reporting data, while portal stores the user-managed definitions. Its table is not moved or recreated by this change. The report calculation remains unfinished. No source-server queries or Finance database changes are involved.
